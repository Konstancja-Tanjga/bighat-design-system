# Adding a component

## First, the bar

A component earns its place when a product would otherwise build a worse
version of it — not when the library looks incomplete without it.

That means the argument for a new component is evidence, not symmetry.
`DS-GAPS.md` records what was reached for, what got hand-rolled instead, and
what the hand-rolled version does worse. The last part is the only argument
that counts. "Every design system has a Stepper" is not one.

## Two homes, one source of truth

A component lives in two places: the Big Hat library in Figma, where it is
designed, reviewed and used to compose screens, and this repository, where it
ships. They are kept in step on purpose, and when they disagree **the code
wins** — `tokens/*.tokens.json` is the source the Figma variables were
generated from, not the other way round.

That does not make Figma a copy. A decision can start there: the 4px radius
grid was set in the library first. What it cannot do is stay there. A value
changed in Figma and not in `tokens/` is drift, and it is resolved by a pull
request that moves the token, or by putting the Figma value back.

## The order, and why it is this order

**1. Write the contract first.** `spec/components/<name>.json`, before any
drawing or code: purpose, what it is _not_ for, anatomy, states, the keyboard
map, the ARIA contract, the tokens it consumes. `npm run spec:validate` tells
you what is still missing.

The contract is what lets the same component exist in Figma, in React and in
the sibling [Angular library](https://github.com/Konstancja-Tanjga/bighat-design-system-angular)
without three people guessing which parts are the design and which are
incidental. Writing it first makes every other step a translation.

**2. Design it in Figma, from the library.** Every fill, stroke, radius, gap
and size is bound to a Big Hat variable — the `Color` collection for roles, in
Light and Dark, `Size` for spacing and radii, `Type` for the face. The
primitives are hidden from the pickers for the same reason product code may not
use them. If no role fits, that is a missing token: propose it in
`tokens/semantic.tokens.json`, not as a local value in one file.

Name the variant properties after the props: `variant`, `size`, `state`, with
the values code uses (`primary`, `md`, `disabled`). The component description
carries the purpose and the "do not use it for" line from the contract, so the
designer reaching for it in the Assets panel reads the same warning a developer
reads in the contract's `notFor`.

Review happens here, in Light and Dark, before anything is built — a frame of
instances that switches the Color mode is the cheapest place to find a state
nobody drew.

**3. CSS in `src/styles/components/<Name>.css`.** BEM parts matching the
contract's `anatomy`, tokens only. The drift audit fails the build on a
literal, which is the intended way to find out that the system is missing a
role.

**4. React in `src/components/<Name>/`.** The props are the Figma variant
properties, under the same names. The Angular library translates from the
contract, idiomatically rather than line by line.

**5. Stories and docs.** `node scripts/scaffold-docs.mjs src spec/components`
writes a story file
and an MDX page from the contract: anatomy, props, states, keyboard, tokens.
What it cannot write is the judgement — when to use it, what to use instead,
the do/don't with reasons — so it leaves TODO markers, and `npm run check:docs`
fails until they are gone.

**6. Tests for every state in the contract.** A state listed in the contract
and not asserted in a test is a state nobody is watching.

**7. Connect Figma to the code.** A Code Connect template in
`figma/<Name>.figma.ts` maps each Figma property to its prop, so Dev Mode shows
the `<Component>` a developer would write rather than CSS read off the canvas.
Leave defaults out of the snippet: a primary, medium button reads
`<Button>Save</Button>`.

**8. Release both sides.** A changeset for the package — `npm run verify`
regenerates the ARIA conformance report and the drift report on the way — and,
once it merges, a new publish of the Figma library with the same note.
Publishing is a person's step on both sides: it is a commitment to every team
using the library.

## Naming

PascalCase, and the same name everywhere it appears: the Figma component, the
Storybook title, the React export, the Angular selector stem, the contract
filename. Story titles once disagreed with their export names in twelve places
— `Toolbar` shipped as "Function Bar" — so searching Storybook for the thing
you were importing found nothing.

Where the designer-facing word is genuinely better, it goes in the contract's
`aliases`, and search matches both. The identifier stays the identifier.

## What does not need a component

A layout. A one-off arrangement of existing components is a page, and putting
it in the library means owning every consumer's version of it forever. If it
recurs enough to matter, it is a template — `Templates/` exists for exactly
that, and templates are allowed to be opinionated in ways components are not.
