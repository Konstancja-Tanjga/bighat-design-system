Figma MCP

Agent kodujący czyta plik Figma przez serwer MCP. Dostaje opis komponentu z jego kontraktem i zmienne z nazwami CSS, więc pisze kod z biblioteki, a nie z pikseli.

Ta sama nazwa w każdym miejscu

To jest sedno. Właściwość w Figmie nazywa się tak samo jak prop w kodzie i ma te same wartości. Projektantka, programista i agent mówią o przycisku tymi samymi słowami.

Code Connect, czyli kod w Dev Mode

Każdy komponent ma w repozytorium szablon, który zamienia właściwości z Figmy na propsy. Wartości domyślne są pomijane, więc domyślny przycisk to po prostu <Button>. Poniżej są snippety skopiowane z Dev Mode.

Button, Tone = critical, Size = lg, State = disabled 
import { Button } from "@bighat/ui"

<Button tone="critical" size="lg" disabled>
  Button
</Button>
Input, State = invalid 
import { Input } from "@bighat/ui"

<Input
  label="Invoice number"
  placeholder="e.g. INV-2041"
  error="This field is required."
/>
Toast, Tone = critical, to wywołanie, nie element 
import { useToast } from "@bighat/ui"

notify({
  tone: 'critical',
  title: 'Title',
  description: 'A short line…',
});

Snippetów nie widać bez płatnego miejsca Dev lub Full w moim zespole Figma. Dlatego pokazuję je tutaj, a na żywo pokażę je na swoim ekranie.

Figma MCP, czyli co czyta agent

Każdy komponent w Figmie ma opis napisany jak kontrakt: do czego służy, do czego nie, jak właściwości mapują się na propsy i jakich tokenów używa. Agent kodujący, na przykład Claude, czyta ten opis przez serwer MCP Figmy razem ze zmiennymi. Dzięki temu buduje ekran z @bighat/ui i nazw tokenów, a nie odtwarza wygląd z pikseli.

An action the user takes. NOT for navigation (that is an anchor), a bookmarkable destination, or a two-state toggle (Switch).

Props → code: Variant = variant ("primary" | "secondary" | "ghost", how much weight), Tone = tone ("neutral" | "critical", what happens if you press it), Size = size, Loading = loading, Icon start/end = iconStart/iconEnd (decorative), Label = children (required, there is no icon-only button).

Code: import { Button } from '@bighat/ui'. Contract: spec/components/button.json.

Jak to sprawdzić w pięć minut

  1. Otwórz Button w Storybooku i zmień w kontrolkach variant oraz size.
  2. Kliknij zakładkę Design pod podglądem. Zobaczysz ten sam zestaw wariantów z Figmy.
  3. Otwórz plik Figma, przejdź na stronę Button i zaznacz komponent. W prawym panelu zobaczysz jego właściwości i opis z kontraktem.
  4. Porównaj nazwy właściwości z Figmy z kontrolkami w Storybooku i z plikiem Button.tsx.
  5. Snippety z Dev Mode i pracę agenta przez MCP pokażę Ci na krótkim nagraniu albo na rozmowie.
