# NavRail

The narrow icon rail down the edge of an application — four to eight
destinations, always visible, never scrolled away.

<Canvas of={NavRailStories.Default} />

## When to use it

| Use `NavRail` for                                           | Use something else for                                                              |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Top-level destinations whose names fit in one or two words  | Anything needing a longer name, a description or a count — use `NavList` in a panel |
| Navigation that must stay visible while the content scrolls | A list of records or conversations — use `NavList` or `ListView`                    |

The boundary is the length of the name, and it is not a layout preference. An
icon-only rail is a memory test: the user has to have learned what each glyph
means before the rail is worth anything. That trade is only fair when the label
is short enough to become a caption the day it turns out the glyph was not
obvious. "Invoices" survives that; "Regulatory reporting archive" does not, and
an icon standing in for it is a puzzle with a tooltip as the answer key.

## The label is required, and it is not a caption

`label` is a required field on every item, and it does three jobs: it is the
accessible name, it is the `title` tooltip, and it is the visible caption when
`showLabels` is on. There is no way to build an item without one.

<Heuristic name="Recognition rather than recall">
  An icon-only rail asks the user to recall; a caption lets them recognise. `showLabels` is the
  cheapest way to move from one to the other, which is why it is a boolean and not a redesign.
</Heuristic>

<Canvas of={NavRailStories.WithLabels} />

Turn captions on past about five destinations. Below that a person can hold the
mapping; above it they are counting positions, and the vertical space a caption
costs is cheaper than the click that goes to the wrong place.

## Active is an attribute, not a highlight

The current item carries `aria-current="page"` alongside its tint. The
attribute is what a screen reader announces and what survives high-contrast
mode, a monochrome display, and anyone who cannot separate two close greys.

Where the icon set supports it, spend the `FILL` axis on this too: a filled
glyph for the current destination and an outlined one for the rest says "you
are here" a second way, without adding colour. Foundations → Iconography has
the axes.

## The badge is a dot, on purpose

`badge` renders a dot, not a number. A rail is 56px wide and a number in it is
either unreadable or the widest thing on the screen — and "17" tells the user
nothing they can act on from here anyway. The dot says _something changed_; the
count belongs where the user can do something about it, in the panel or the
list the rail leads to.

## Two rails need two names

<Canvas of={NavRailStories.TwoRails} />

Each rail is a `<nav>` landmark, and `ariaLabel` names it. A screen reader
lists landmarks by name, so two rails both called "Primary" — or both unnamed —
give the user two identical entries and no way to choose. The default is
`"Primary"` because most applications have exactly one; the second one is the
consumer's to name.

## Props

| prop          | values  | default     | meaning                                                                 |
| ------------- | ------- | ----------- | ----------------------------------------------------------------------- |
| `items`       | data    | —           | `id`, required `label`, `icon`, optional `badge`.                       |
| `activeId`    | string  | —           | The current destination. Draws the tint and sets `aria-current="page"`. |
| `onSelect`    | event   | —           | Called with the item's `id`.                                            |
| `footerItems` | data    | —           | Pinned to the bottom — settings, account, help.                         |
| `showLabels`  | boolean | `false`     | Captions under each icon. Prefer it past about five destinations.       |
| `ariaLabel`   | string  | `'Primary'` | Names the landmark, so two rails can be told apart.                     |

## Accessibility

- **Role** — `navigation` landmark containing a list of buttons
  (implicit, from `<button[type=button]>`).
- **Labelling** — required. The landmark takes `ariaLabel`; each item takes its
  name from `label`, through `aria-label` when the caption is hidden and from
  the visible caption when it is not — never both, which would announce the
  name twice.
- **Focus** — one tab stop per item, in document order, footer items last.
  A rail holds a handful of destinations, so the arrow-key pattern would cost
  more in discoverability than it saves in keystrokes.
- **Announcements** — none. The destination announces itself when it loads;
  a live region here would say the same thing a moment earlier and a moment
  louder.
